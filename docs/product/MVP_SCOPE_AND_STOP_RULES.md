# MVP Scope and Stop Rules

상태: **CANONICAL / FEATURE FREEZE**  
기준일: 2026-07-17

## 1. 동결 선언

QRPick Opportunity Pipeline은 현재 구현을 MVP 기준선으로 동결한다. 목적은 기능 수를 늘리는 것이 아니라 4주간 실제로 사용해 상위 후보가 영업 행동으로 전환되는지 검증하는 것이다.

신규 수집기, AI API, 첨부파일 파싱, OCR, 웹 UI, CRM, 자동 이메일, 제안서 자동화는 구현하지 않는다.

## 2. MVP에 포함되는 기능

| 기능 | MVP 계약 | 현재 상태 |
|---|---|---|
| 수집 | 공개 지원사업, 구현된 MICE 행사 소스, G2B 용역 4단계 | 구현/부분 구현 |
| 정규화 | 날짜별 원본을 도메인별 표준 레코드로 변환 | 구현 |
| 중복 제거 | 확실한 중복만 병합하고 불확실성 보존 | 구현, 교차 도메인은 미구현 |
| MICE·QRPick 분류 | 설명 가능한 규칙과 근거·신뢰도 | 구현 |
| 조달 생애주기 | 사전규격·입찰·낙찰·계약의 강한 연결 | 부분 구현 |
| 영업 경로 | 직접입찰·컨소시엄·솔루션 파트너·낙찰사 영업 | 조달 중심 구현 |
| Top 30 | 도메인 원점수를 쓰지 않는 제품 전체 운영자 기본 출력 | 구현 |
| 전체 원장 | raw, 도메인 normalized, 통합 JSONL/all CSV 보존 | 구현 |
| 판정 근거 | reasons/evidence/confidence/unknowns | 구현 |
| 권장 행동 | 다음 검토·접촉 행동 텍스트 | 구현, 상태형 task는 미구현 |
| manifest | 소스·stage·건수·상태·오류 | 도메인별 부분 구현 |
| 테스트 | 주요 규칙·오류·보안·Top 30 회귀 테스트 | 구현 |
| 실행 | Windows batch와 Python CLI | 구현 |

`부분 구현` 항목은 자동으로 신규 개발 항목이 되지 않는다. 현재 주간 운영을 막는 결함인지 4주 기록으로 먼저 확인한다.

## 3. MVP 필수 산출물

- raw 원본과 collection errors
- normalized 대표 레코드와 normalization errors
- duplicates 또는 lifecycle link 근거
- collection manifest와 통계
- G2B `procurements.jsonl`
- `unified-opportunity-top30.csv`
- `unified-opportunity-all.csv`
- `unified-opportunities.jsonl`
- `unified-opportunity-manifest.json`
- 근거·미확인 사항·권장 다음 행동
- 테스트 결과와 실행 로그

## 4. MVP 완료 판정

### 기능 완료

- 필수 파이프라인이 문서화된 batch/CLI로 실행된다.
- 원본 500건 등 전체 데이터가 원장에 보존되고 운영 기본 출력만 제한된다.
- Top 30이 우선순위 규칙대로 정렬되고 중복 경로가 한 행으로 통합된다.
- 상세 미검증 후보의 `GO`/`ACTION_NOW`가 0이다.
- 부분성공·실패·truncation·인증 부재가 manifest에 드러난다.
- 전체 테스트가 통과한다.

### 운영 완료

- 4주 연속 주간 플레이북을 수행한다.
- 매주 Top 30에서 Top 10, Top 3~5를 선택한 근거와 결과를 기록한다.
- 오탐, 미탐, 미실행 사유, 수동 검토 시간을 기록한다.
- 기능 요청이 아니라 실제 반복 병목 목록이 만들어진다.

운영 완료 전에는 MVP를 “제품 효과 검증 완료”로 표현하지 않는다.

## 5. 명시적 비범위

- 범용 조달 AI SaaS
- 모든 RFP 전수 분석
- 자동 입찰·지원·제출
- 자동 GO/NO-GO
- CRM 전체 대체
- 제안서 자동 생성
- 여러 회사 대상 멀티테넌트
- 대규모 웹 대시보드
- 고객용 서비스
- 신규 source registry 확장 또는 신규 collector
- 첨부 다운로드·RFP 파싱·OCR
- AI 상세심사·AI 재랭킹
- 자동 담당자 탐색·자동 이메일
- 행동 task의 자동 생성·배정·발송

## 6. 변경 허용 범위

기능 동결 중 허용:

- 데이터 손실, 잘못된 0건, parsing/status 오류 수정
- API 키·개인정보 노출 차단
- 상세 미검증 `GO`/`ACTION_NOW` 등 위험한 과대표현 수정
- 명백한 오탐·미탐의 공통 규칙 결함 수정
- 공식 소스 구조 변경으로 기존 MVP가 중단된 경우의 유지보수
- 재현성, manifest, 테스트, 문서 drift 결함 수정
- 의존성 보안 업데이트
- 내부 조회용 최소 정적 UI는 4주 운영 검증을 위한 승인 예외 범위로 허용한다.

허용되지 않음:

- 단일 후보를 위한 제목 하드코딩
- 운영 기록 없이 scoring 차원 추가
- “나중에 필요할 수 있음”을 이유로 한 레이어·DB·API 추가
- 새 소스, 새 UI, 새 AI 기능을 결함 수정으로 포장

## 7. 즉시 중단 조건

다음이 발견되면 해당 운영 실행을 중단하고 결함을 수정한다.

- raw 원본 또는 전체 후보 손실
- API 키·비공개 개인정보 노출
- 로그인·CAPTCHA·접근통제 우회
- manifest가 실패를 성공으로 표시
- 동일 실행에서 원본·정규화·대표 건수 추적이 설명되지 않음
- 상세·첨부 미검증 레코드가 `GO`, `VERIFIED_ELIGIBLE`, `ACTION_NOW`로 표시
- Top 30에 `NO_ACTION` 포함
- 직접·파트너 중복이 별도 행으로 반복되어 운영 건수를 부풀림
- 테스트 실패 상태의 운영 배포

## 8. 유지 또는 동결 후보

| 대상 | 결정 | 이유 |
|---|---|---|
| `app/dashboard/` | 동결 | 웹 UI는 비범위 |
| `app/proposal_pipeline/` | 동결 | 제안서 자동화는 비범위 |
| 추가 MICE source registry 구현 | 동결 | 현재 소스의 운영가치 검증 우선 |
| 경량 통합 opportunity 출력 | 유지·동결 | 최종 출력에만 구현됨; 도메인 모델로 확장 금지 |
| 상태형 action queue/CRM | 동결 | 외부 운영 기록으로 4주 검증 |
| 기존 경로별 CSV | 유지 | 감사·세부 분석용, 운영 기본 파일은 Top 30 |
| `skills/ir-search/` | 수정 금지 | upstream 권위 |

삭제는 이번 동결 작업에 포함하지 않는다.

## 9. 향후 기능 공통 진입 조건

다음을 모두 만족해야 동결 해제를 검토한다.

1. 4주 이상 실제 운영
2. 반복 병목 또는 손실을 주간 지표로 확인
3. 주당 발생 빈도와 수동 소요시간 측정
4. 현재 규칙·문서·운영 절차로 해결 불가
5. 예상 매출 또는 비용 절감과 구현·운영비 비교
6. 보안·개인정보·약관 검토
7. 성공지표와 철회 조건 합의
8. 제품 책임자의 명시적 승인

## 10. AI 상세심사 진입 조건

다음을 **모두** 만족해야 한다.

- 4주 이상 실제 운영
- 주당 상세검토 후보 10건 이상
- RFP 독해 시간이 반복 병목으로 확인
- 추출할 항목과 허용값 표준화
- 정답 표본과 사람 검토 절차 준비
- AI 결과가 실제 영업·입찰 결정에 사용될 가능성 확인
- 비밀정보 전송, 저장, 비용, 오류 책임 검토

조건 충족 후에도 AI는 요약·추출 보조이며 최종 GO/NO-GO 결정자가 아니다.

## 11. 4주 후 의사결정

- **유지:** Top 30이 반복적으로 Top 3~5 행동을 만들고 현재 수동 절차가 감당 가능
- **결함 수정:** 오탐·누락·상태 오류가 반복되나 기능 확장 없이 해결 가능
- **제한적 고도화 검토:** 명확한 반복 병목과 투자효과가 확인됨
- **중단/축소:** 후보가 실제 행동으로 전환되지 않거나 운영 비용이 가치보다 큼
