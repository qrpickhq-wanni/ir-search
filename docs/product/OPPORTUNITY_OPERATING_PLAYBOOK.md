# Opportunity Operating Playbook

상태: **CANONICAL**  
주기: 매주 1회, 필요 시 조달 마감 전 추가 실행

## 1. 운영 목표

후보 수를 늘리는 것이 아니라 매주 다음 흐름을 완료한다.

> 수집 → Top 30 확인 → Top 10 상세검토 → Top 3~5 행동 → 결과 기록

파이프라인은 후보와 근거를 제공하고, 사람은 상세 확인·우선순위 조정·접촉·입찰 판단을 담당한다.

## 2. 역할

| 역할 | 책임 |
|---|---|
| 파이프라인 운영자 | 실행, manifest·오류·건수 확인, Top 30 전달 |
| 영업 검토자 | Top 10 선정, 접촉 경로와 메시지 준비 |
| 입찰 검토자 | 첨부·자격·예산·일정·수행범위 확인 |
| 제품 책임자 | Top 3~5 행동 승인, 결과·미실행 사유 기록, 동결 해제 판단 |

한 사람이 여러 역할을 맡을 수 있으나 단계별 판단은 기록한다.

## 3. 주간 실행 전 점검

- 작업 루트가 `C:\git_hub\work\qrpick-opportunity-pipeline`인지 확인
- `.venv`와 `requirements.txt` 설치 상태 확인
- 필요한 API 키를 환경변수로만 설정
- 키·개인정보가 화면 공유, 명령 기록, 로그에 노출되지 않는지 확인
- 같은 날짜 산출물을 덮어쓰는지 확인하고 필요한 경우 별도 run 폴더 사용
- `skills/ir-search/`와 raw JSONL을 수정하지 않음

## 5. 실행 품질 확인

보고서를 열기 전에 다음을 확인한다.

1. collection manifest가 존재하는가.
2. 인증 부재, `PARTIAL_EXPECTED`, `PARTIAL_UNEXPECTED`, `FAILED`, `OK_TRUNCATED`가 있는가.
3. stage/source별 요청·수집·파싱·필터·저장 건수가 설명되는가.
4. normalization errors와 duplicates가 비정상 증가하지 않았는가.
5. raw 원본과 normalized 원장의 날짜·입력 경로가 맞는가.
6. 테스트가 통과했는가.

인증 부재로 빈 파일만 생성된 구조 검증은 영업 운영 성공이 아니다. truncation이 있으면 전체 수집으로 표현하지 않는다.

## 6. Top 30 검토

기본 파일:

- `g2b-pre-notice-top30.csv`: 운영자 기본 30건
- `g2b-pre-notice-all-candidates.csv`: 영업 후보 전체
- `procurements.jsonl`: NO_ACTION을 포함한 전체 조달 원장

Top 30에서 확인:

- 우선순위와 공개일
- MICE 적합 신뢰도와 원문 근거
- QRPick·Showda 역할 근거
- 주경로와 보조경로
- 예산과 공개 연락경로
- 미확인 사항과 검토 기한
- 원문 URL

금지:

- P0를 자동 GO로 해석
- 직접입찰 경로를 자격 확정으로 해석
- 전체 행사 운영 용역을 QRPick 단독 수행 가능으로 단정
- 공개 근거 없는 담당자·이메일 생성

## 7. Top 10 상세검토

Top 30에서 다음 기준으로 Top 10을 사람이 선택한다.

1. 공고가 최신이며 철회·마감되지 않았는가.
2. 상세 페이지와 첨부에 접근 가능한가.
3. 과업에 등록·체크인·배지·웹·데이터·매칭 역할이 명시되는가.
4. 전체 행사 기획·연출 비중이 크다면 현실적인 PCO/기획사 경로가 있는가.
5. 예산, 수행기간, 행사일, 본공고 예정일이 확인되는가.
6. 업종·실적·지역·면허·공동수급·하도급 조건이 무엇인가.
7. 공개 연락처 또는 파트너 후보가 확인되는가.
8. QRPick·쇼다가 제공할 구체 범위와 제외 범위가 무엇인가.

상세검토 결과:

- 직접입찰 검토 계속
- 컨소시엄/파트너 전환
- 낙찰사 영업 대기
- 추가 조사
- watch
- 제외/오탐

## 8. Top 3~5 행동

각 행동에 최소한 다음을 기록한다.

- 사업/사전규격번호
- 선택한 경로
- 접촉 대상 또는 확인할 기관
- 이번 주 한 가지 행동
- 담당자
- 목표일
- 기대 결과
- 차단 요인

행동 예:

- 첨부·자격 체크리스트 작성
- 발주기관 공개 문의처에 본공고 일정 확인
- PCO/기획사 후보에 QRPick 역할·견적 범위 제안
- 낙찰사 공개 연락처로 시스템 공급 여부 확인
- 내부 직접 수행역량 검토

자동 이메일·자동 제출은 하지 않는다.

## 9. 결과 기록

매주 다음 지표를 기록한다.

| 지표 | 정의 |
|---|---|
| Top 30 유효 건수 | 중복·철회·명백한 오탐을 제외하고 검토 가치가 있던 수 |
| 상세검토 건수 | 원문 상세 또는 첨부·자격을 사람이 확인한 수 |
| 직접입찰 검토 | 직접입찰 체크리스트를 수행한 수 |
| 파트너 접촉 | PCO·기획사·입찰사에 실제 접촉한 수 |
| 낙찰사 접촉 | 낙찰사에 실제 접촉한 수 |
| 회신 | 유효 회신 수 |
| 상담 | 미팅·통화 등 상담 전환 수 |
| 견적 | 견적 범위를 작성·전달한 수 |
| 제안서 | 제안서 작성 또는 제출 수 |
| 계약 | 계약 또는 유상 공급 수 |
| 오탐 | 상위 후보였으나 MICE·역할·경로가 부적합한 수 |
| 미탐 | 사람이 별도로 발견했으나 파이프라인이 놓친 수 |
| 미실행 사유 | 시간 부족, 연락처 없음, 자격 불명, 시기 경과 등 |

권장 주간 기록 필드:

```text
week
run_date
top30_valid
detail_reviews
direct_bid_reviews
partner_contacts
awardee_contacts
replies
consultations
quotes
proposals
contracts
false_positives
false_negatives
not_executed_reason
manual_review_minutes
notes
```

현재 저장소는 CRM이 아니므로 이 기록은 승인된 내부 스프레드시트/문서에서 관리해도 된다. 개인정보는 최소화한다.

## 10. 4주 운영표

| 주차 | 필수 실행 | 회고 질문 |
|---|---|---|
| 1주 | 전체 흐름 1회, 기준 시간 측정 | Top 30을 이해하는 데 무엇이 부족했는가 |
| 2주 | 같은 지표 반복, 오탐 사유 분류 | 반복 오탐이 규칙 문제인가 상세 부족인가 |
| 3주 | 접촉·회신 전환 확인 | 경로와 권장 행동이 실제 접촉에 도움이 되는가 |
| 4주 | 누적 지표와 병목 정리 | 유지·결함 수정·제한적 고도화·중단 중 무엇인가 |

매주 규칙을 즉시 바꾸지 않는다. 보안·데이터 손실·과대표현 결함을 제외하면 최소 2회 이상 반복된 문제를 개선 후보로 기록한다.

## 11. 에스컬레이션

즉시 중단:

- API 키 또는 비공개 개인정보 노출
- raw/원장 데이터 손실
- 실패가 성공으로 표시
- 상세 미검증 `GO`/`ACTION_NOW`
- Top 30 중복 또는 NO_ACTION 포함

다음 주 결함 검토:

- 반복 오탐·미탐
- 원문 URL·기관·날짜 추적 누락
- manifest 건수 불일치
- 공식 소스 구조 변경

4주 후 제품 검토:

- 통합 Top 30 필요성
- action 상태 관리 필요성
- RFP 독해 병목과 AI 진입 조건
